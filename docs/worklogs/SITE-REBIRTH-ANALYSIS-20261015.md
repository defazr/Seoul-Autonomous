## 0. 한 줄 결론

사이트가 "가치 없는 콘텐츠" 로 4번 거절된 이유는 디자인이 아니라 **정체성과 수요의 불일치**다.
사이트의 SSoT·브랜드·영문 우선 구조는 "외국인을 위한 자율주행 11노선 가이드" 인데,
실제 방문의 90% 이상은 **한국인 · 모바일 · 네이버 · 심야버스(N버스) 노선도 한 페이지**다.
재탄생의 핵심은 스크롤 디자인이 아니라 **"서울 심야 이동 라이브 보드" 로 제품을 다시 세우는 것**이고,
디자인은 그 위에 얹는다. URL 은 전부 보존하고 N버스 노선·허브 페이지를 **추가**한다.

## 3. 진단 — 세 가지 불일치

1. 정체성 불일치: 잠금된 제품 목표("서울에서 지금 어디서 무엇을 타야 하는지, 공식 근거와 함께 판단하는 한·영 심야 이동 서비스")
   는 맞다. 그런데 구현은 "자율주행 11노선 디렉터리 + 외국인 영어 우선" 이고, 그 11노선은 하루 수십 명이 타는
   시범 노선이라 검색 수요가 거의 없다. 데이터는 N버스가 주인공이라고 말한다.
2. 가치 불일치: "지금" 을 답하려면 실시간이 필요한데 69 URL 중 1 URL 만 실시간이다. 나머지는 5개월 전 기준일 표.
3. 형식 불일치: 텍스트·표 전용. 이미지 0, 지도는 손으로 그린 SVG 도식 1장(노선도 페이지 전용). 모바일 심야 사용자가
   원하는 것은 "내 위치 근처 정류장 · 다음 차 · 몇 분" 이지 문단이 아니다.

디자인 리뉴얼만 하면 1·2 가 남는다. 1·2 를 풀면 디자인은 자연히 "지도와 보드" 중심이 된다.

## 4. 제안 — "Seoul After Midnight": 서울 심야 이동 라이브 보드

### 4.1 제품 재정의 (포그린 결정 사항)

```
주인공      서울 심야버스(올빼미버스) 14노선 + 공항 심야버스(N6000·N6001·N6002·N6701·N6703 — 공식 확인 필요)
차별 요소   자율주행 심야A21·새벽 A노선 (기존 SSoT 11노선 — 그대로 보존, 보조 축으로 이동)
핵심 가치   "지금 몇 시, 어디서, 무엇이, 몇 분 뒤" — 도착·차량 위치를 서버 프록시로 라이브 표시 + 공식 근거
언어        한국어 1순위, 영어는 공항·허브·노선 핵심 페이지만 (현재 EN 트래픽 실측 거의 0)
사용자      막차 놓친 귀가자·대리기사·야간 근무자·새벽 출근자·공항 심야 이동자 (+ 외국인은 공항축으로 유입)
URL         기존 69 URL 전부 보존 (리다이렉트 0). 신규 추가만:
             /ko/night-bus/n61 … 14개 (+ en 선택)
             /ko/hubs/gangnam-station … 허브 10~20개 (정류장 전량 금지 유지)
             /ko/airport-night-bus (+ en)
```

### 4.2 홈 = 스크롤 라이브 보드 (디자인 컨셉)

```
S1 히어로      풀블리드 지도 캔버스. 스크롤에 따라 14 노선이 색선으로 그려지고 "지금 운행 중 N개 노선 · 다음 출발 허브" 가 겹친다.
               23:00~06:00 밖에서는 "오늘 밤 첫차 23:00 까지 n시간" 과 낮 운행 A노선 안내로 전환 (실시간처럼 보이는 거짓 표현 0)
S2 허브 보드   강남역·홍대입구·종각·서울역·동대문·잠실·신촌·건대… 카드. 카드마다 N노선 칩 + 도착 2건 ("HH:MM 기준" 명시)
S3 노선 갤러리  가로 스냅 스크롤. 노선 색 띠 · 기점→종점 · 첫차/막차 · 배차. 탭하면 노선 페이지
S4 결정 플로우  출발·도착 입력 → 직통/환승 + 환승 지점 + 다음 차 (현 노선도 로직 + 라이브 결합)
S5 가이드      요금·환승·탑승법·막차 이후 (기존 4개 가이드 재조판)
S6 자율주행     심야A21·새벽 A노선 (기존 자산) — "일반 버스와 다른 점" 으로 포지셔닝
S7 신뢰        출처·확인일·운영자·업데이트 로그 (E-E-A-T)
```

노선 페이지: 노선 색 히어로 → 지리 지도(MapLibre) 에 경로·정류장·차량 위치 점 → 정류장 타임라인(스크롤 스파인,
방향 토글, 각 정류장 탭 시 도착) → 첫차/막차/배차/운임 → 환승 가능 N노선 → FAQ → 출처.
허브 페이지: 도착 보드(이 정류장의 N·A 노선 전부) → 승강장·방향 안내 → 지도 → 근처 허브.

모션 원칙: CSS scroll-driven animation(animation-timeline) + prefers-reduced-motion 존중. LCP 는 텍스트·정적 지도
이미지가 먼저, 캔버스·라이브는 hydration 후. CLS 예산 0.05 (RT-2 pilot 0.0994 보다 엄격).
시각 언어: 딥 네이비·블랙 밤 팔레트 + 노선 14색(현 ROUTE_COLORS 승계) + 시안 포인트 유지. 타이포 Pretendard+Geist 유지 가능.

## 7. CC 이견 및 아이디어

1 이견: "완전히 다른 디자인" 보다 "완전히 다른 주인공" 이 먼저다. 디자인만 바꾸는 라운드는 반대한다. 디자인은 R2 에서 제품 재정의 위에 한다.
2 이견: 영어 우선 구조는 실측상 근거가 없다. 영어는 공항·허브·노선 핵심만 남기고 한국어를 1순위로 돌리자. (외국인 축은 공항 심야버스가 입구)
3 리스크: 네이버가 사실상 유일한 유입원인데 네이버는 웹문서 노출이 약하다. 노선별 페이지 14 + 허브로 롱테일(N15·N61…)을 잡는 것이 구글보다 빠른 성과가 될 가능성이 크다.
4 아이디어: 허브 보드를 "지금" 뿐 아니라 "오늘 밤 마지막 차" 카운트다운으로 — 심야 사용자의 진짜 질문은 "아직 탈 수 있나" 다.
5 아이디어: 노선도 PNG 저장 기능(현재 존재)을 노선별 카드 이미지 공유(OG·스레드·카톡)로 확장 — Threads 유입 15 세션이 이미 있다.
6 아이디어: AI 어시스턴트 유입(chatgpt 20 세션)이 구글과 같다. 노선 페이지에 구조화 데이터(BusTrip/BusStop schema)와 명확한 사실 문장을 넣으면 AI 인용이 늘어난다.
7 아이디어: 수익화는 AdSense 단일 의존을 줄이는 것도 검토 대상 — 카카오 AdFit(웹 가능)·제휴는 포그린 판단.
