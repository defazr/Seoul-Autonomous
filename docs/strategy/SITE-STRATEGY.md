## 1. 사이트 정체성

### 포지션

Seoul Autonomous는 **서울 자율주행버스·로보택시 정보를 사람이 이해하기 쉽게 정리한 AI 검색 대응형 지식베이스**를 지향한다.

이 사이트는 실시간 교통앱이 아니다. 노선 검색 도구가 아니다.
**검증된 정보를 구조적으로 정리해 사용자와 AI 검색이 신뢰할 수 있는 출처가 되는 것**이 목표다.

### 하지 않는 것

- 실시간 교통앱 대체 X
- 카카오맵/네이버지도 대체 또는 임베드 중심 사이트 X
- 모든 버스 노선 DB 경쟁 X
- 수동 글 양산 X

### 하는 것

- routes.json 기반 검증된 자율주행 노선 정보 정리
- 자동 생성 가능한 페이지 구조 우선 설계
- 정보 기준일과 출처를 명확히 표기
- AI 검색이 인용하기 쉬운 신뢰 페이지 운영
- 네이버 검색 트래픽은 자동 생성 페이지 + 본문 롱테일로 흡수

## 2. 단일 데이터 원본 원칙

### routes.json = SSoT

routes.json은 이 사이트의 단일 데이터 원본이다.
모든 페이지의 노선/정류장/운행 정보는 routes.json에서 파생된다.

### 추가 데이터 소스 정책

routes.json 외 추가 데이터 소스는 원칙적으로 만들지 않는다.
필요 시 routes.json 확장으로 처리한다.

새 데이터 소스 도입은 다음 조건에서만 검토한다.
- routes.json 구조로 표현 불가능한 데이터 유형
- 포그린 명시 승인
- SSoT 변경 절차 준수

## 3. 페이지 유형 분류

이 사이트의 모든 페이지는 다음 4개 유형 중 하나에 속한다.

### 자동 생성형 (우선순위 최상)

routes.json에서 자동 생성되는 페이지.

예시:
- 노선 목록 (/routes)
- 노선 상세 (/routes/[id])
- 지역 허브 (/areas/[area])
- 운행 시간대별 그룹 페이지

특징:
- routes.json 변경 시 자동 갱신
- 유지보수 비용 낮음
- 페이지 양산에 유리

### 수동 작성형 (신중하게)

콘텐츠를 직접 작성해야 하는 페이지.

예시:
- How to Ride
- 가이드 페이지 (자율주행버스란, 무인버스 차이 등)
- About / 운영 정책

조건:
- 출처 audit 필수
- 정확성 리스크 평가 필수
- 콘텐츠 변경 시 수동 갱신 필요
- 수동 글 양산 금지 — 한 페이지의 가치가 명확할 때만 추가

### 법적 필수형

배포 전 필요한 법적/운영 페이지.

예시:
- Privacy
- Terms

특징:
- 앱 v1 내용 재사용 가능
- SEO 가치 낮음
- 배포 단계에서 필수

### SEO 인프라형

페이지 자체가 사용자에게 보이지 않거나 검색 시스템 대상.

예시:
- sitemap.xml
- robots.txt
- JSON-LD 구조화 데이터
- OG 메타데이터

특징:
- 모든 페이지에 자동 적용
- AI 검색 인용에 직접 영향
- 페이지 정리 후 일괄 적용 효율적

## 4. 정확성/출처 정책

### 확정 vs 추정 분리

모든 정보는 확정/추정으로 분리해 표기한다.

- 확정: routes.json 또는 앱 v1에 명시된 검증 정보
- 추정/미확정: 외부 출처, 변동 가능 정보, 데이터 부재 항목

### Unknown 처리

데이터 부재 항목은 "—"로 표기한다.
"정보 없음", "확인 중" 같은 모호한 표기 금지.
실시간성 표현 금지.

### 정보 기준일

모든 자동 생성 페이지는 데이터 기준일(lastChecked)을 표시한다.
수동 작성 페이지는 페이지별 기준일을 명시한다.

### 탑승 전 확인 안내

운행/요금/예약 등 변동 가능 정보가 포함된 페이지는 다음 안내를 포함한다.
- "탑승 전 카카오맵/공식 안내를 확인하세요"
- 앱 패턴 그대로 이식 (별도 신규 작성 금지)

## 5. AI 검색 대응 가설 전략

### 가설 기반 명시

AI 검색 대응은 확정된 성공 공식이 아니라 가설 기반 전략이다.
ChatGPT, Perplexity, 네이버 큐, Google AI Overview 등이 어떤 페이지를 인용하는지 검증된 패턴이 부족하다.

따라서 이 사이트는 다음 가설에 기반해 설계된다.

### 작업 가설

- 신뢰성 높은 출처는 AI 검색에 인용될 가능성이 높다
- 구조화된 데이터(JSON-LD)는 인용 정확도를 높인다
- 출처 명시와 정보 기준일은 신뢰 신호다
- 정기 업데이트 가능한 구조는 시간이 지나도 유효하다

### 우선순위 원칙

위 가설에 따라 다음 4가지를 우선한다.
- 신뢰성
- 구조화
- 출처 명시
- 업데이트 가능성

### 효과 검증

전략 효과는 배포 후 다음 데이터로 측정한다.
- Google Search Console
- 네이버 서치어드바이저
- 서버 로그 (User-Agent, Referer)
- AI 검색 인용 여부 (수동 모니터링)

데이터 기반으로 전략을 조정한다. 검증 없이 가설을 진리로 박지 않는다.

## 6. 네이버 SEO 전략

### 기본 원칙

- 자동 생성 우선
- 수동 양산 금지
- 롱테일은 본문 분산

### H1 정책

H1은 정확한 대표 키워드로 짧게 유지한다.
검색량 욕심으로 H1을 길게 만들지 않는다.

예시:
- "서울 자율주행버스 타는 법" (How to Ride 한국어)
- "청계천 자율주행버스 노선" (지역 허브 가설)

### 본문 롱테일 분산

H1에 못 넣는 키워드는 본문, H2, FAQ에서 자연 분산한다.

예시:
- "무인버스" 키워드는 H1 X, 본문 O
- 자연 문장으로 흡수: "서울 무인버스라고 검색하는 분들이 찾는 자율주행버스 이용 방법"

### 검색량 현실

서울 자율주행 키워드는 현재 검색량이 작다.
대형 트래픽 사이트가 아니라 선점형 주제로 본다.
시장이 커질 때를 대비한 페이지 구조 우선.

## 7. 운영 원칙

### 페이지 추가 기준

새 페이지는 다음 기준을 통과해야 한다.

- 사이트 정체성과 일치
- routes.json 자동 생성 가능 여부 검토 완료
- 정확성/출처 audit 완료
- SEO 가치 또는 신뢰 페이지 가치 명확
- 유지보수 부담 평가 완료

위 기준 미충족 시 추가하지 않는다.

### 업데이트 정책

- routes.json 변경 = 자동 생성형 페이지 자동 갱신
- 수동 작성형 페이지는 분기별 검토
- 정확성 정책 변경은 모든 페이지 일괄 적용

### Unknown 처리 운영

routes.json의 Unknown 필드는 v1.1에서 점진적 보강한다.
보강 전까지는 "—" 표기 유지.
추정으로 채우지 않는다.

### 페이지 양산 한계

SSoT 11번 = "1차 30~35페이지"는 하한선이다.
다만 페이지 양 자체가 목표가 아니다.
**관리 가능한 구조 안에서 양산한다.**

## 8. 안전장치 (필수)

### 8.1 전략 문서 ≠ 지시서

이 전략 문서는 라운드별 지시서를 대체하지 않는다.
Claude Code는 전략 문서를 근거로 지시서 범위를 임의 확장하거나 사양을 변경할 수 없다.

모든 작업은 라운드별 지시서를 따른다.
지시서에 없는 작업은 수행하지 않는다.

### 8.2 가설 기반 전략

AI 검색 대응은 확정된 성공 공식이 아니라 가설 기반 전략이다.
신뢰성, 구조화, 출처 명시, 업데이트 가능성을 우선하고,
효과는 배포 후 GSC/네이버/로그 데이터를 보며 조정한다.

전략 변경 시 이 문서를 갱신하고 변경 이력에 기록한다.

### 8.3 사양 단독 변경 금지

Round 7B에서 SVG 기반 구현이 CSS div 기반 구현으로 변경된 사례를 교훈으로 삼는다.

지시서 사양에서 벗어나는 방향으로 갈 때는:
- 먼저 보고
- 사양 내 해결책을 먼저 시도
- 시도 흐름을 보고에 명시
- 단독 결정 금지

### 8.4 포그린 최종 결정 원칙

페이지 추가, 라운드 순서, 전략 변경, 데이터 소스 확대 여부는 포그린이 최종 결정한다.
Claude UI와 Claude Code는 제안과 실행만 담당한다.

전략 해석 권한은 포그린에게만 있다.
