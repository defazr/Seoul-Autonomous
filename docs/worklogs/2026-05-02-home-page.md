**Date:** 2026-05-02

## i18n Library Decision

**Selected: next-intl 4.11.0**

- Native Next.js App Router support with `[locale]` route segments
- Server components support (no client-only limitation)
- ICU message format (compatible with app's i18next `{count}` interpolation — adjusted from `{{count}}` to `{count}`)
- MIT license
- Next.js 16 compatibility confirmed (build + runtime)
- Middleware warning: Next.js 16 deprecated `middleware.ts` in favor of `proxy` convention, but middleware still functions correctly

## Root / Handling

**Option A: Redirect to /en** (chosen)

- `app/page.tsx` uses `redirect('/en')` for all root requests
- HTTP 307 redirect confirmed
- SEO-safe: search engines follow redirects, `/en` is the canonical
- Simple and deterministic — no Accept-Language header parsing complexity

## Route Structure

```
/           → 307 redirect to /en
/en         → Home (English)
/ko         → Home (Korean)
/en/*       → future pages
/ko/*       → future pages
/design-preview → component preview (unaffected by i18n)
```
