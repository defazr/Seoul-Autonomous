## I. 세션 중 FIX 2건 (둘 다 완료)

### FIX 1 — budget accounting (계약 위반 수정)

fixture 호출인데 `budget=1/300` 이 증가하던 문제. **차감 지점을 `fetchUpstream` 내부,
실제 `fetch()` 직전으로 이동**했다.

```
검증: fixture 3회 → upstream call 로그 0건 · 차감 0        PASS
회귀: budget=0 게이트 여전히 작동 / partial 정상            PASS
```

> 이건 "dev라서 무해"한 문제가 아니었다. **budget 카운터가 실제 upstream 호출량을 뜻한다는 의미**가
> 깨지면, "300에 근접 = 캐시 이상 신호"라는 판단 근거 자체가 무너진다.

### FIX 2 — `setTimeout(…, 0)` lint 우회 제거

lint 통과용으로 한 틱 미루던 코드를 **정상 패턴으로 교체**했다.

- **I/O를 컴포넌트 밖 순수 함수로 분리** — `fetchArrivals(stopId, signal)` 은 setState 하지 않고
  `{kind:'ok'|'failed'|'aborted'}` 만 반환
- **상태 갱신은 완료 콜백에서만** — `void fetchArrivals(...).then(apply)`

lint 규칙이 원래 권장하는 *"외부 시스템 구독 + 콜백에서 setState"* 형태다.
**eslint disable·suppression 0 · baseline 유지 · TECH-DEBT 기록 불요.**

## S. CC 이견 및 아이디어

### ① 지시서에 대한 이견

### ② 정정 1건

CLS 관련해 CC 가 *"필드 p75는 0에 가까울 것"* 이라고 쓴 것은 **추정을 확정처럼 서술한 오류**다.
실제 사용자 분포를 보기 전에는 알 수 없다. 판정은 **`Pilot ACCEPT / expansion WATCH`** 로만 기록한다.

### ③ 리스크

- **B 상태 CLS 0.0994는 fixture 기준 dev 측정치**다. 실제 운행 시간대의 카드는 노선 수·문자열 길이가
  달라 높이가 바뀌므로 **수치가 달라질 수 있다.** 확장 전 재측정 시 감안해야 한다.
- **`/tmp/rt2-real.sh` 는 재부팅에 사라진다.** J-1 이 며칠 뒤로 밀리면 스크립트부터 다시 만들어야 한다.
- **인증 확인은 시점 스냅샷**이다. 마이페이지 승인 확인(08-28)과 J-1 사이가 벌어지면
  인증 오류가 날 수 있고, 이를 "노선 미지원"으로 오독하면 안 된다.
- **process-local 캐시·budget 은 토폴로지 의존**이다. 현재 단일 컨테이너라 사실상 global 이지만,
  인스턴스를 늘리면 실질 상한이 `300 × N` 이 된다. 재배포 counter 리셋까지 고려하면
  `300 × 3 = 900 < 1,000` 이라 **현재 수치에서만 안전**하다. budget 을 올리면 이 여유가 사라진다.
