## Round 25-G.2 — 브랜드형 404 실험 (BLOCK → 보류)

### 목표였던 것
Next.js 기본 404("404: This page could not be found." 흰 화면)를 브랜드형(헤더·홈/지도 링크 포함) 404로 교체. 세 경로 유형:
- A. locale 내부 없는 경로(`/ko/does-not-exist`) → catch-all `[locale]/[...rest]/page.tsx` → notFound()
- B. 정상 라우트인데 데이터 없음(`/ko/routes/N99`, `/en/night-bus-fare`) → 페이지의 notFound()
- C. locale 없는 경로(`/night-bus-fare`, `/fr`) → root `app/not-found.tsx`

### 왜 BLOCK인가 (확정된 사실)
- **`output: 'standalone'` 프로덕션(`node .next/standalone/server.js`)에서 21개 404 케이스 전부 기본 `__next_error__` 스텁으로 떨어짐.** 커스텀 not-found가 아예 안 쓰임
- **서버 로그 에러 0** — 렌더 크래시가 아니라 standalone 라우팅이 커스텀 not-found를 서빙하지 않는 동작
- **프리렌더 산출물 `_not-found.html`에는 커스텀 콘텐츠가 정상 존재**하나 요청 시점엔 스텁이 나감
- **dev 서버(`next dev`)에서는 정상 렌더**됨 → dev/standalone 차이
- 유력 용의자: `output: 'standalone'` + **passthrough root layout**(`app/layout.tsx`가 `return children`, `<html>` 없음) 조합. 하지만 미확정
- 안정 기능만으로 풀려면 root layout에 `<html>` 추가가 필요해 보이는데, 이는 **53페이지 전체 최상위 렌더 구조 변경 + next-intl의 `[locale]/layout` `<html>`과 이중 충돌 위험** → 포그린이 root layout 변경 금지 확정
- **제약**: 실제 배포 Dockerfile은 서버에 untracked로만 존재, CoWork가 볼 수도 수정할 수도 없음. 단 현재 라이브가 이미 기본 404를 보여줘서 standalone이 대표성 있음

### 포그린 최종 결정 (2026-07-12)
- **404 UX 개선 = 보류 (비차단 기술부채).** 없는 URL의 HTTP 404·noindex는 정상이라 SEO·크롤러 무해, AdSense 거절 사유 아님
- root layout 수정 / Next·next-intl 업그레이드 / Dockerfile·배포 방식 변경 / experimental.globalNotFound / middleware·rewrite — **전부 금지 유지**
- 404 화면 하나 위해 사이트 전체 구조를 흔들지 않는다

### 실험 흔적 보존 위치 (재개 시)
- `/tmp/round25g2-404-wip.patch.tar.gz` — 6개 파일 tar(경로 그대로): `app/not-found.tsx`(+css), `app/[locale]/not-found.tsx`, `app/[locale]/[...rest]/page.tsx`, `components/not-found/NotFoundView.tsx`(+css)
