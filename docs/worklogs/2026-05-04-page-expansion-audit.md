## 5. routes.json 신규 필드 평가

### F1: `fare_model`
- 제안: 'free' / 'fixed' / 'metered' 구분
- 기존 `fare` 필드와의 관계: fare는 현재 전부 "Unknown". fare_model은 요금 체계 유형을 분류하는 새 필드
- 적용 가능 노선:
  - 새벽동행(A160, A741, A148, A504): Gemini "무료 운영 중" → 'free' (1차 출처 확인 필요)
  - cheonggye-a01: Gemini "현재 무료, 하반기 유료화 예정" → 'free' (1차 확인 필요)
  - gangnam-robotaxi: Gemini "2026-04 고정요금제 유료화" → 'fixed' (1차 확인 필요)
  - 기타: 정보 부재
- 1차 출처 확인 필요 항목:
  - 새벽동행 무료 여부 (서울시 보도자료)
  - 청계천 무료 여부 및 유료화 시점 (A2Z 공식)
  - 강남 로보택시 고정요금 금액 (SWM 보도자료)
- **적합성: 보류** — 개념은 적합하나, 현재 fare 필드 자체가 전부 Unknown. fare 필드 보강이 선행되어야 함. fare_model은 fare 보강과 동시에 도입하는 것이 효율적.

### F2: `operator_contact`
- 제안: 운영사 고객센터 번호
- 기존 `operator` 필드와의 관계: operator도 전부 "Unknown". contact 추가 전에 operator 확보가 선행
- 1차 출처 확인 필요: 각 운영사 공식 웹사이트/연락처
- 사이트 정체성 정합성: △ — 연락처 노출은 유용하나, 사이트가 "고객센터 디렉토리"가 되면 정체성 흐려짐
- **적합성: 보류** — operator 필드 보강 선행 필요. contact는 operator 확보 후 검토.

### 보류 필드: `safety_stats`
- 평가 제외 (지시서 §8.2). 1차 출처 부재.

### 기존 필드 보강 검토
- `appRequired`: 11/11 Unknown. Gemini: 청계천은 TAP! 앱 필수, 강남은 카카오T. 1차 출처 확인 후 보강 가능
- `appName`: onDemandServices의 gangnam-robotaxi에만 "Kakao T" 있음. fixedRoutes에는 appName 필드 자체 없음
- **권고: 기존 필드 보강** — appRequired, fare, operator, daysOfOperation 보강이 신규 필드 추가보다 우선. v1.1 데이터 보강 라운드에서 일괄 처리 권고.
